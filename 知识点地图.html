第一层Python 语言本身

这一层和 AI 毫无关系，纯粹是 Python 基本功。好消息是：这几条会了，后面所有代码都长一个样。

01字典和嵌套取值现在就要懂

step1 第①步、第④步

字典就是「键 → 值」的对照表，用 {} 表示。{"role": "user"} 意思是：键 role 对应值 user。

API 返回的东西层层嵌套，所以取值要一层层剥：data["choices"][0]["message"]["content"]。读法是——先从 data 里拿 choices，它是一个列表，取第 0 个；再从那个字典里拿 message；再拿 content。

列表用数字索引，字典用键名。记住这一句就够。

30 秒验证
d = {"a": [{"b": "找到了"}]}
print(d["a"][0]["b"])     # 找到了
print(d["a"][1])          # 报错 IndexError，因为只有 1 个元素
02json.dumps 和 json.loads现在就要懂

step1 第②步、第④步

Python 的字典只活在 Python 里，发不到网络上。网络上传的只能是文本。所以要在两者之间来回翻译：

json.dumps(字典) → 字典变文本（发出去之前）
json.loads(文本) → 文本变字典（收到之后）

记法：dumps 的 d 是 dump（倒出去），loads 的 l 是 load（装进来）。结尾的 s 是 string，表示处理的是字符串。

30 秒验证
import json
text = json.dumps({"name": "小明", "age": 20})
print(text)                 # {"name": "\u5c0f\u660e", "age": 20}
print(type(text))           # <class 'str'>  这是文本
back = json.loads(text)
print(back["name"])         # 小明
03字节和字符串：encode / decode现在就要懂

step1 第②③步、step2 读每一行

这是新手报错最多的地方。文本（str）是给人看的，字节（bytes）是给机器传的。网络只认字节。

.encode("utf-8")：文本 → 字节，发出去之前要做。
.decode("utf-8")：字节 → 文本，收到之后要做。

规律一句话：出编码，进解码。搞反了就会看到 TypeError: a bytes-like object is required 或者满屏乱码。

30 秒验证
s = "你好"
b = s.encode("utf-8")
print(b)          # b'\xe4\xbd\xa0\xe5\xa5\xbd'  这是字节
print(len(b))     # 6   一个汉字占 3 个字节
print(b.decode("utf-8"))   # 你好
04try / except：出错不要直接崩现在就要懂

step1 第③步、step2 发请求处

正常情况下代码一行行往下走。但如果网络断了、key 错了，Python 会直接抛异常停下，屏幕上全是红字。

try 里放「可能出事的代码」，except 里放「出事了怎么办」。这样程序不会崩，你还能打印出人话。

我在这里专门接住了 HTTPError——它带着一个 .code 属性，就是状态码，所以能告诉你 401 还是 402。

重点不是语法，是意识：所有要联网的代码都必须包 try。这是面试里「你怎么保证系统不崩」的第一层答案。

05环境变量和 os.environ.get现在就要懂

step1 第 17 行

环境变量是操作系统里的一张「全局便签」，程序可以读，但不会写进代码文件。

为什么要绕这一圈？因为代码会被上传到 GitHub。一旦 key 写死在代码里，全世界的爬虫几分钟内就会扫到它，然后刷你的余额。这种事每年都在发生。

os.environ.get("DEEPSEEK_API_KEY") 的意思是：去便签上看有没有这一条，没有就返回 None，不会报错。

step1 里我用 or "..." 做了个兜底，让你能直接把 key 填在代码里先跑起来——这是练习期的临时手段，不是正确做法。后面 step4 会改成从 .env 文件读。

06if __name__ == "__main__"看懂就行

两个文件最末尾

一个 .py 文件有两种命运：要么被你自己运行，要么被别的文件 import 进去用。

这一行的意思是：只有「被直接运行」时才执行下面的 main()；如果是被 import 的，就别自动跑起来。

不写会怎样？别人 import 你的文件时，你的代码会莫名其妙开始执行。所以这是标准写法，照抄就行。

07空字符串是「假」的看懂就行

step1 的 if not API_KEY、step2 的 if piece

Python 里这些东西都算 False：空字符串 ""、空列表 []、空字典 {}、数字 0、None。

所以 if not API_KEY: 读作「如果 key 是空的，就提示用户」。if piece: 读作「如果这片内容不是空的，才打印」——因为有些片段确实没有正文，只有格式信息。

这比写 if API_KEY == "": 更地道，你会在所有 Python 项目里看到这个写法。

08.get() 和 [] 的区别看懂就行

step2 的 chunk.get("choices")、delta.get("content")

d["key"]：键不存在 → 直接抛 KeyError，程序停。
d.get("key")：键不存在 → 返回 None，程序继续。

自己的数据用 []，外部来的数据用 .get()。因为服务器返回的 JSON 结构你无法 100% 保证（比如最后一帧就没有 choices），用 [] 会直接崩。

这一条背后是个更大的原则：不要相信外部输入。面试里问「你怎么保证系统不崩」，这是第二个答案。

09with 语句看懂就行

step1 第③步、step2 读流的位置

网络连接用完必须关掉，否则资源泄漏。with 的作用是：出了这个代码块，自动帮你关，哪怕中途报错也会关。

不用 with 就得自己写 response.close()，还容易忘。属于「知道它负责收尾」就够。

10for 循环遍历一个「文件一样的东西」看懂就行

step2 的 for raw_line in response

平时 for 遍历的是列表。这里遍历的是网络响应对象，但它被设计得像文件——可以一行一行读。

关键点：它不会一次把内容全读进内存，来一行给一行。这正是流式能成立的原因。如果换成 response.read()，就会卡住等全部收完。

11字符串的 strip / startswith / 切片看懂就行

step2 每一行的处理

.strip()：去掉两头的空白和换行。服务器发的每行结尾都有 \n，不去掉没法比。

.startswith("data:")：判断开头是不是这几个字符，返回 True/False。

line[5:]：切片，从第 5 个字符取到末尾，就等于「砍掉前 5 个字符」。我写成 line[len("data:"):] 是为了让人一眼看出砍掉的是什么，效果一样。

12print 的 end 和 flush看懂就行

step2 打印每个碎片的地方

print() 默认两个行为：结尾自动换行、内容先存缓冲区攒着。

end="" 改成不换行，flush=True 改成立刻显示。

不写 flush，你会等全部结束才「唰」一下看到全文，然后以为自己流式写错了。这个坑我提前告诉你。

13f-string 字符串插值先知道

f"Bearer {API_KEY}"

字符串前面加个 f，里面用 {} 就能把变量的值塞进去。比 "Bearer " + API_KEY 好读，也不会因为类型不同报错。

14标准库和第三方库先知道

文件开头的几个 import

json、os、urllib 是 Python 自带的，装好 Python 就有，不用 pip。requests 是别人写的，要 pip 装。

所以 step1 和 step2 你什么都不用装就能跑——这是故意的。等 step4 我们再换成 requests，那时候你会明白它好在哪。

15函数定义与 -> None先知道

def main() -> None:

-> 后面写的是「这个函数返回什么类型」。None 就是什么都不返回。

这只是给人看的提示，Python 不会强制检查。但它是专业代码的标配，实习时你的 code review 会被提这个。

第二层HTTP 与网络

调大模型 90% 的工作量在这里。这一层搞懂了，「调 API」这件事就彻底不神秘了。

16HTTP 请求的四个零件现在就要懂

step1 第②步

任何一个 HTTP 请求都由这四样组成，一个都不能少：

地址（URL）——发给谁，https://api.deepseek.com/chat/completions
方法（method）——要干什么。POST = 我要提交数据给你处理
请求头（headers）——附带说明，比如我是谁、我发的是什么格式
请求体（data）——真正的内容，就是那段 JSON

你以后看任何 API 文档，都是在告诉你这四个填什么。看懂这一条，你就具备了「照文档接入任意 API」的能力。

17Authorization 和 Bearer token现在就要懂

"Authorization": f"Bearer {API_KEY}"

服务器怎么知道是你？靠请求头里的这一行。

Bearer 的意思是「持有者」——谁拿着这个 token，就当作谁。所以 token 等于密码，泄露就是钱没了。

注意 Bearer 后面有一个空格，很多人栽在这，报 401 查半天。

18Content-Type：声明你发的格式看懂就行

"Content-Type": "application/json"

告诉服务器「我发的是 JSON」。为什么必须说？因为同一堆字节，可能是 JSON，也可能是表单、是图片、是纯文本。服务器得知道怎么解析。

不发或发错，常见结果就是 400，或者服务器收到一堆乱码。

19状态码：先看第一位看懂就行

except 里打印 error.code

不用背具体数字，记第一位就够：

2xx 成功　4xx 你错了（请求有问题）　5xx 服务器错了

常用几个：401 key 不对　402 余额不足　429 请求太频繁被限流　400 参数写错　500/503 服务器自己出问题

这个区分决定了要不要重试——4xx 重试一百次也一样，5xx 和 429 才值得等一会儿再试。step3 就讲这个。

20timeout 为什么必须有看懂就行

urlopen(request, timeout=60)

不加超时，如果服务器卡住不回你，你的程序会永远等下去，界面看起来就是死了。

这是线上事故的经典成因之一。原则：任何跨网络调用都必须设超时，没有例外。

21SSE：服务器怎么「一行一行」发数据现在就要懂

step2 整个读取循环

SSE 全称 Server-Sent Events，是一种「服务器持续往客户端推数据」的简单协议。规则非常朴素：

每行以 data: 开头，后面跟一段文本，行与行之间用空行隔开。就这么两条。

所以你会看到空行（分隔用，要跳过）和 data: [DONE]（DeepSeek 自己约定的结束标记，不是 SSE 标准的一部分，但大家都在用）。

这个知识点直接对应实习工作内容：你要做一个网页聊天界面，后端就得用 SSE 往前端推字。今天读的这段代码，将来是你写的那段代码。

22GET 和 POST 的区别先知道

GET 是「我要东西」，参数挂在网址后面，能被浏览器历史记录下来。
POST 是「我给你东西」，参数在请求体里，不出现在网址上。

发对话内容用 POST，两个原因：内容太长塞不进网址；而且对话内容不该出现在日志和浏览记录里。

23urllib 和 requests 的关系先知道

urllib 是 Python 自带的，功能全但用起来啰嗦（你看 step1 要手写 Request 对象）。

requests 是第三方的，一行 requests.post(url, json=body, headers=h) 就完事，还能自动处理很多细节。

我先让你用 urllib，是为了让你看见底下的结构。等 step4 换 requests 时，你会觉得「原来它替我做了这些」——这比直接用 requests 学到的多。

第三层大模型接口本身

这一层才是 agent 开发真正的地基。只有 5 条，但每一条后面都会反复用到。

24messages 数组和 role现在就要懂

step1 第①步

对话不是一段文字，而是一个列表，每个元素是一句话，每句话带一个身份：

system —— 设定人格和规则，相当于给模型的岗位说明
user —— 用户说的
assistant —— 模型之前说的

这是后面所有东西的基石。工具调用的结果、检索到的资料、历史对话，全都是往这个列表里塞新元素。第 5 周手写 agent 循环，本质上就是在管理这个列表。

25模型没有记忆现在就要懂

step1 的 messages 只有一个元素

这是最反直觉、也最重要的一条：模型不记得你上一句说了什么。它是无状态的。

你觉得 ChatGPT 记得上下文，是因为程序每次都把整段历史重新发了一遍。第二轮请求里，messages 会有 3 条；第十轮就有 21 条。

由此推出三个后果，全是实习面试的高频题：
· 对话越长，发的 token 越多，越贵越慢
· 长到超过「上下文窗口」就会被截断或报错
· 所以需要「记忆管理」——摘要、裁剪、检索历史

这一步只要记住「每轮都要全量重发」，就够了。

26message 和 delta 的区别看懂就行

step1 取 message，step2 取 delta

message：完整的一整段回答，非流式才有。
delta：增量，这一片新增的内容，流式才有（delta 就是「差值」的意思）。

所以从 step1 改到 step2，取答案的位置必须跟着变，这是最容易被忽略的一处。

27choices 为什么是个列表先知道

data["choices"][0]

因为接口支持「一次给我生成 N 个不同版本让你挑」，那个参数叫 n。我们没传，所以列表里永远只有 1 个，取 [0] 就对。

知道这个，你就不会觉得 [0] 是个莫名其妙的魔法数字。

28token 是什么先知道

模型不按「字」算，按 token 算。一个 token 大约是一个英文单词，或者半个到一个汉字。

两件事都和它有关：计费按 token 算，上下文窗口（能一次吃多少）也按 token 算。

所以「省成本」和「避免超长」本质是同一件事：控制发过去的 token 数。现在不用深究怎么数，知道有这回事即可。

如果今天只记五件事

  1. 调大模型 = 发一个 HTTP POST。地址、方法、请求头、请求体，四样凑齐就行。
  2. dict 和 JSON 要互相翻译。出用 dumps，进用 loads。
  3. 出编码，进解码。发之前 encode，收之后 decode。
  4. 模型没有记忆，每轮都要把整段历史重发。这句话能解释后面 80% 的设计。
  5. 联网的代码必须包 try，必须设 timeout。这是工程意识的第一课，也是面试送分题。
